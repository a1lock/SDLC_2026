# ИС «Склад»

Серверная часть информационной системы автоматизации складского учета материалов
(ТЗ-ИС-СКЛАД-01): REST API на FastAPI, PostgreSQL 17, миграции Alembic.
Веб-интерфейс (Jinja2/HTMX) в состав этой части не входит; документация API
формируется автоматически и доступна по адресу `/docs` (OpenAPI 3).

## Что реализовано

| Функция ТЗ | Метод API | Роли |
|---|---|---|
| Ф6. Вход, JWT на 60 мин | `POST /auth/login`, `GET /auth/me` | все |
| Ф1. Число поставщиков материала | `GET /materials/{code}/suppliers/count` | кладовщик, администратор |
| Ф2. Добавление единицы хранения | `POST /storage-units` | кладовщик, администратор |
| Просмотр ЕХ (постранично) | `GET /storage-units`, `GET /storage-units/{id}` | кладовщик, администратор |
| Ф3. Список поставщиков материала | `GET /materials/{code}/suppliers` | кладовщик, администратор |
| Ф4. Число поставщиков банка по адресу | `GET /banks/suppliers/count?zip=&city=&street=&house=` | кладовщик, администратор |
| Ф5. Справочники | `GET`, `POST`, `PUT`, `DELETE` на `/materials`, `/units`, `/suppliers`, `/documents`; `/materials/{code}/units` | чтение — все, изменение — администратор |
| Ф6. Учетные записи | `GET`, `POST`, `PATCH` на `/users` | администратор |
| Диагностика | `GET /health` | все |

Дополнительно к таблице 8 ТЗ реализованы: `DELETE` справочников (запись, на которую есть ссылки,
не удаляется — 409), исправление и удаление ЕХ администратором (п. 4.3.7), управление
пользователями (таблица 5).

Ошибки: 422 — нарушение формата или несуществующий справочный код (с именем поля), 409 — повтор
«номер ордера + дата» или конфликт данных, 404 — запись не найдена, 401/403 — нет токена/прав,
429 — вход заблокирован, 503 — БД недоступна. Запись ЕХ сохраняется одной транзакцией.
Справочники отдаются с `ETag` и поддерживают `If-None-Match` → `304 Not Modified`.

## Запуск

```bash
cp .env.example .env
# Задайте POSTGRES_PASSWORD, JWT_SECRET (openssl rand -hex 32), ADMIN_LOGIN и ADMIN_PASSWORD.
docker compose up --build -d
curl http://localhost:8000/health
```

При старте контейнер применяет миграции (`alembic upgrade head`) и создает первого
администратора из `ADMIN_LOGIN`/`ADMIN_PASSWORD`, если его еще нет. Затем откройте
<http://localhost:8000/docs>: получите токен через `POST /auth/login` и вставьте его
в «Authorize».

Контрольный пример приемки (п. 6.6 ТЗ) и тестовые учетные записи:

```bash
docker compose exec app python -m scripts.seed --users-password 'ПарольДляДемо1'
docker compose exec app python -m scripts.seed --bulk 100000   # нагрузочный набор: 100 000 ЕХ
```

Скрипт идемпотентен. Контрольный пример загружается напрямую в БД, поэтому ордера от
декабря 2026 года появляются независимо от сегодняшней даты.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DATABASE_URL` | — (обязательна) | адрес PostgreSQL |
| `JWT_SECRET` | — (обязательна, ≥ 32 символов) | ключ подписи токенов |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | 60 | срок токена, не более 60 |
| `LOGIN_MAX_ATTEMPTS` / `LOGIN_LOCK_MINUTES` | 5 / 15 | блокировка входа |
| `BCRYPT_ROUNDS` | 12 | стоимость bcrypt |
| `APP_TIMEZONE` | Europe/Moscow | «текущая дата» для проверки даты ордера |
| `LOG_LEVEL` | INFO | уровень журнала («время, уровень, модуль, сообщение») |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | — | первый администратор |

## Разработка и тесты

```bash
pip install -r requirements-dev.txt
ruff check .
pytest --cov                      # SQLite в памяти
TEST_DATABASE_URL=postgresql://user:pass@localhost/sklad_test pytest --cov   # PostgreSQL, как в CI
```

Автотесты включают все 14 проверочных тестов контрольного примера (таблица 21),
негативные тесты контроля реквизитов, права ролей, блокировку входа, поведение при
недоступной БД и проверку миграций. Порог покрытия — 70 % (`fail_under`).
CI: `.github/workflows/ci.yml` (PostgreSQL 17, Ruff, pytest).

Новая миграция: `alembic revision --autogenerate -m "описание"`, применение —
`alembic upgrade head`, откат — `alembic downgrade -1`.

## Резервное копирование

`scripts/backup.sh` делает `pg_dump` и хранит 14 последних копий (п. 4.1.8). Пример для cron:

```
0 3 * * * cd /opt/sklad && BACKUP_DIR=/mnt/backup/sklad ./scripts/backup.sh
```

Восстановление: `docker compose exec -T db pg_restore -U sklad -d sklad --clean < файл.dump`.
Архивирование журналов WAL раз в час (восстановление на момент времени) настраивается
администратором на уровне PostgreSQL и в состав приложения не входит.

## Принятые решения

- **Сортировка Ф3** — по наименованию поставщика, поэтому для материала 1001 сначала идет
  «АО «СтальСнаб»» (102), затем «ООО «Металлоторг»» (101).
- **Дата ордера** проверяется на «не позже сегодняшней» по `APP_TIMEZONE`, как в таблице 7.
  Ордер 5 от 10.12.2026 из теста № 9 будет принят начиная с 10.12.2026.
- **Адрес банка (Ф4)**: сравнение без учета регистра и лишних пробелов; адреса поставщиков при
  сохранении нормализуются (обрезка и схлопывание пробелов). Для быстрого поиска, кроме индекса
  по ТЗ, создан функциональный индекс по `lower(...)`.
- **Блокировка входа** хранится в памяти процесса: при перезапуске приложения счетчики
  сбрасываются; приложение рассчитано на один процесс Uvicorn.
- **Токен** проверяется по подписи, срок и активность учетной записи — по БД при каждом запросе,
  поэтому отключенный пользователь теряет доступ сразу.
- **Числа** в JSON передаются и возвращаются строками (`"25000.00"`) без потери точности;
  на вход принимаются и числа.
- **Коды справочников** можно задавать вручную (например, коды ОКЕИ) или не указывать — тогда
  назначается следующий свободный.
- **Версии**: в `requirements.txt` указано `SQLAlchemy>=2.0.43` вместо 2.0.36 из ТЗ — для
  совместимости с Python 3.14. Остальные версии из ТЗ сохранены.
